  <files>
src/app/components/Dashboard.tsx
  </files>
  <action>
Upgrade the dashboard stat cards to use Framer Motion spring hover states.

1. Import from animations.ts:
```tsx
import { hover, springs } from "@/lib/animations";
```

2. Find the stat card wrapper elements (the Cards or divs containing each stat metric).

3. Convert each stat card to a `motion.div` (or wrap the existing Card component) and add:
```tsx
<motion.div
  whileHover={hover.lift}
  transition={springs.snappy}
  className="..." // keep existing classes
>
  {/* existing card content */}
</motion.div>
```

**What `hover.lift` does:** `{ scale: 1.015, y: -2 }` with snappy spring physics. The card subtly lifts and enlarges — feels physically weighted, not a linear CSS transition.

**Key details:**
- If the stat card already uses `whileHover` (e.g., `scale: 1.02`), replace with `hover.lift` for consistency
- Add `cursor-pointer` if the card is clickable; otherwise `cursor-default`
- Do NOT add hover to cards that are purely informational and have no click action — only interactive-feeling cards
- The spring transition makes the card feel like it has mass — this is perceptible and different from CSS `transition: transform 0.2s`
- Box shadow should also elevate on hover. If the card uses CSS shadow, add a hover shadow class. If using Tailwind: add `hover:shadow-lg` alongside the motion hover.

  <action>
Replace simultaneous card appearance with staggered entrance animations using variants from animations.ts.

1. Import from animations.ts:
```tsx
import { staggerContainer, fadeUp } from "@/lib/animations";
```

2. Find the card grid container (the element wrapping the stat cards — typically a `div` with `grid` or `flex` classes).

3. Convert the grid container to a `motion.div` with stagger variants:
```tsx
<motion.div
  variants={staggerContainer}
  initial="hidden"
  animate="visible"
  className="grid grid-cols-1 md:grid-cols-2 lg:grid-cols-4 gap-4" // keep existing grid classes
>
```

4. Convert each child card wrapper to use the `fadeUp` variant:
```tsx
<motion.div variants={fadeUp}>
  {/* Card content */}
</motion.div>
```

**How it works:**
- Parent `staggerContainer` has `staggerChildren: 0.06` — each child starts 60ms after the previous
- Child `fadeUp` animates from `{opacity: 0, y: 12}` to `{opacity: 1, y: 0}`
- Combined effect: cards cascade in from top to bottom with a subtle upward motion
- `delayChildren: 0.1` gives a brief pause before the first card appears

**Key details:**
- Apply stagger to ALL card grid sections on the Dashboard (stats row, widget row, recent activity)
- If the Dashboard already uses manual delay offsets (e.g., `transition={{ delay: 0.1 }}`, `delay: 0.2`), replace them with the stagger pattern — manual delays are what MOT-03 wants to eliminate
- The stagger variants automatically inherit from parent — child motion.divs only need `variants={fadeUp}`
- MotionConfig handles reduced-motion — stagger animations won't fire when OS accessibility setting is on
