  <action>
EmberParticles uses Canvas API with requestAnimationFrame — MotionConfig's `reducedMotion="user"` does NOT cover it. Add a manual `prefers-reduced-motion` check.

At the top of the component (inside the function body, before any Canvas setup):

1. Add a `useEffect` that checks `window.matchMedia("(prefers-reduced-motion: reduce)")` on mount
2. Store the result in a ref or state
3. Listen for changes via the `change` event on the MediaQueryList
4. If reduced motion is preferred: skip the requestAnimationFrame loop entirely — render a static canvas or return null
5. Clean up the event listener on unmount

IMPORTANT:
- Do NOT remove the existing Canvas rendering logic — only gate it behind the reduced-motion check
- The component already has a cleanup for the RAF loop — make sure the reduced-motion path also cancels any pending frames
- Use `matchMedia.addEventListener("change", handler)` (not the deprecated `addListener`)

Example pattern:
```tsx
const [prefersReducedMotion, setPrefersReducedMotion] = useState(() => {
  if (typeof window === "undefined") return false;
  return window.matchMedia("(prefers-reduced-motion: reduce)").matches;
});

useEffect(() => {
  const mql = window.matchMedia("(prefers-reduced-motion: reduce)");
  const handler = (e: MediaQueryListEvent) => setPrefersReducedMotion(e.matches);
  mql.addEventListener("change", handler);
  return () => mql.removeEventListener("change", handler);
}, []);

// Early return before canvas setup
if (prefersReducedMotion) return null;
```
