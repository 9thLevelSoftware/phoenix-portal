**Active state detection:** Use `useLocation()` to derive `isActive`:
```tsx
const isActive = location.pathname === item.path || (item.path !== "/dashboard" && location.pathname.startsWith(item.path));
```
Pass `isActive` to `SidebarMenuButton`'s `isActive` prop. The shadcn component will set `data-[active=true]` which triggers `bg-sidebar-accent text-sidebar-accent-foreground` (already wired to `rgba(255,107,53,0.1)` and `#FF6B35` in theme.css).

**2px left ember accent bar:** Inside the NavLink, when active, render:
```tsx
{isActive && <span className="absolute left-0 top-1 bottom-1 w-0.5 bg-primary rounded-full" />}
```
NavLink needs `className="relative"` for this to position correctly.

**Avatar dropdown (SidebarFooter):**
- Use DropdownMenu wrapping the avatar button
- DropdownMenuTrigger shows: Avatar (initials fallback from useAuth profile), display name, TierBadge, streak with Flame icon
- In icon-rail mode (use `useSidebar().state === "collapsed"`), show only the avatar circle
- DropdownMenuContent items: Profile (link to /profile), Settings (link to /integrations), Subscription (link to /pricing), DropdownMenuSeparator, Logout (calls signOut from useAuth)
- Display name and tier badge hidden in collapsed mode via `group-data-[collapsible=icon]:hidden`

**Collapse toggle:** Place `<SidebarTrigger />` (which renders the built-in PanelLeft icon toggle) at the very bottom of SidebarFooter, below the avatar dropdown.

**Auto-collapse hook (useAutoCollapse):** Define inside AppSidebar or as a separate function. Use `useSidebar()` to get `open`, `setOpen`. Use a `useRef` to track user preference. On mount, check `window.matchMedia("(max-width: 1279px)")`. If matches, save `open` to ref and call `setOpen(false)`. On media query change crossing below 1280: save pref to ref, setOpen(false). On crossing above 1280: restore from ref (if ref was true, setOpen(true)). Important: this does write the cookie via setOpen — acceptable because the ref preserves the user's preference separately. When restoring, the ref-based restore overwrites whatever the cookie says.

**Critical anti-patterns to avoid (from RESEARCH.md):**
- Do NOT add sidebar collapsed state to useUIStore (Zustand) — SidebarProvider cookie is the single source of truth
- Do NOT insert extra wrapper divs between AppSidebar and SidebarInset — CSS peer selectors require them as siblings
- Do NOT use NavLink render prop for isActive detection with asChild — use useLocation() instead
