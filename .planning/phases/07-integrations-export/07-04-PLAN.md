Create supabase/functions/fitbit-oauth/index.ts:
- Follow Strava pattern but with Fitbit endpoints
- Token exchange: POST https://api.fitbit.com/oauth2/token
- Fitbit uses Basic auth header: `Basic ${base64(client_id:client_secret)}`
- Request body format: grant_type=authorization_code&code={code}&redirect_uri={redirect}
- Response includes access_token, refresh_token, user_id, expires_in
- Store in user_integrations with token_expires_at calculated from expires_in
- Queue initial sync

Create supabase/functions/fitbit-sync/index.ts:
- Fetch activities from https://api.fitbit.com/1/user/-/activities/list.json
- Parameters: afterDate, sort=asc, offset=0, limit=100
- Token refresh: POST to /oauth2/token with grant_type=refresh_token
- For each activity, normalize and upsert to external_activities

Create src/lib/integrations/fitbit.ts:

- OAuth URL: https://www.fitbit.com/oauth2/authorize
- Scope: activity (for activity data access)

- Include state parameter with userId

Create supabase/functions/garmin-oauth/index.ts:
- Garmin uses OAuth 1.0a (not 2.0!) - more complex flow
- Step 1: Get request token from https://connectapi.garmin.com/oauth-service/oauth/request_token
- Step 2: User authorizes at https://connect.garmin.com/oauthConfirm
- Step 3: Exchange for access token at https://connectapi.garmin.com/oauth-service/oauth/access_token
- Store oauth_token and oauth_token_secret (no refresh token in OAuth 1.0a)
- Note: OAuth 1.0a requires signature generation (HMAC-SHA1)

For simplicity, implement OAuth 2.0 style if Garmin now supports it (check research notes). If OAuth 1.0a required, implement basic structure with TODO for signature.

Create supabase/functions/garmin-webhook/index.ts:
- Garmin supports push notifications for new activities
- Receives POST with activity data when user completes workout
- Validate webhook signature if Garmin provides one
- Extract activity data, normalize, and insert to external_activities
- Return 200 OK to acknowledge receipt
